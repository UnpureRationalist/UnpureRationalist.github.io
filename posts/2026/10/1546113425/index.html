LLM Systems 10 & 11: Accelerating Transformer Training and Inference

0. Recap

Transformer Architecture：

1. Accelerated GPU Computation for Transformer Training

Overview:


对应下面将要介绍的 4 个优化手段：

  • Kernel Fusion：计算图级别优化，通过算子融合减少计算图节点。
  • Reduce synchronization：算子内优化，通过算子实现形式变换，减少 kernel 内同步开销。
  • Mixed-precision Calculation：框架层面优化，混合精度训练提升训练速度，降低显存开销。
  • Memory reuse：细粒度内存管理优化。

1.1 Kernel Fusion

Kernel Fusion Motivation


  • 将多个小 kernel 融合为一个。
  • 减少了 CPU launch kernel 开销。

例子：


  • 三个矩阵相加
    • 朴素实现：先计算 A+B 得到 C，然后计算 C+D 得到最终结果。
      • 需要两次 kernel launch。
      • 需要读显存 4 次，写 2 次。
    • Kernel Fusion：一个 kernel 完成 A+B+D。
      • 需要 1 次 kernel launch。
      • 减少了 1 次显存读和 1 次显存写。

1.1.3 Gradient of Criterion Operator（CrossEntropyLoss）

带 Label Smoothing 的 CrossEntropyLoss forward 流程：

  • Label Smoothing 后目标概率分布 \(p\) ：

\[ p_i = (1 - \alpha) y_i + \frac{\alpha}{V} \]

其中 \(y_i\) 为原始的 One-hot 真实标签，\(\alpha\) 为标签平滑系数，\(V\) 为词表大小。

  • 预测概率分布 \(q\) ：

\[ q_i = \text{Softmax}(x_i) = \frac{e^{x_i}}{\sum_j e^{x_j}} \] 其中 \(x\) 为 logits 向量。

  • 交叉熵损失 \(\mathcal{L}\)：

\[ \mathcal{L} = -\sum_i p_i \log(q_i) \]

  • 朴素实现：
    • Label Smoothing
    • Softmax
    • log
    • 向量内积
  • Kernel Fusion：
    • 输入 Logits \(x\) 和标签 \(y\)，一步到位输出 Loss \(\mathcal{L}\) 和预测概率 \(q\)

反向传播 Fusion 推导：

通过对损失函数 \(\mathcal{L}\) 直接推导关于输入 Logits \(x_k\) 的偏导数（利用 \(\sum_i p_i = 1\) 的性质，Softmax 梯度的分母项与交叉熵求导项相互抵消）：

\[ \nabla_x \mathcal{L} = \frac{\partial \mathcal{L}}{\partial x} = q - p \]

具体推导过程如下：

  • Softmax 导数：

\[ \frac{\partial \mathbf{q}_i}{\partial \mathbf{h}_j} = \begin{cases} \mathbf{q}_i (1 - \mathbf{q}_i), & \text{if } i = j \\ -\mathbf{q}_i \mathbf{q}_j, & \text{if } i \neq j \end{cases} \]

  • 损失函数对 Logit \(\mathbf{h}_i\) 求导：

根据链式法则：

\[ \nabla \mathbf{h}_i = \frac{\partial \mathcal{L}}{\partial \mathbf{h}_i} = -\sum_j \frac{\mathbf{p}_j}{\mathbf{q}_j} \cdot \frac{\partial \mathbf{q}_j}{\partial \mathbf{h}_i} \]

按目标位置 \(i\) 是否为 Ground Truth 分情况讨论：

1) 当 \(i = k\) （即 Token \(i\) 是真实标签）时：

\[ \begin{aligned} \nabla \mathbf{h}_k = \frac{\partial \mathcal{L}}{\partial \mathbf{h}_k} &= -\frac{\alpha}{V} \sum_{j \neq k} \frac{1}{\mathbf{q}_j} \cdot \frac{\partial \mathbf{q}_j}{\partial \mathbf{h}_k} - \left(1 - \alpha + \frac{\alpha}{V}\right) \cdot \frac{1}{\mathbf{q}_k} \cdot \frac{\partial \mathbf{q}_k}{\partial \mathbf{h}_k} \\ &= -\frac{\alpha}{V} \sum_{j \neq k} \frac{1}{\mathbf{q}_j} (-\mathbf{q}_j \mathbf{q}_k) - \left(1 - \alpha + \frac{\alpha}{V}\right) \cdot \frac{1}{\mathbf{q}_k} \cdot \mathbf{q}_k (1 - \mathbf{q}_k) \\ &= \frac{\alpha}{V} \sum_{j \neq k} \mathbf{q}_k - \left(1 - \alpha + \frac{\alpha}{V}\right) (1 - \mathbf{q}_k) \\ &= \frac{\alpha}{V} (V - 1) \mathbf{q}_k - \left(1 - \alpha + \frac{\alpha}{V}\right) (1 - \mathbf{q}_k) \\ &= \mathbf{q}_k - \frac{\alpha}{V} - 1 + \alpha \end{aligned} \]

2) 当 \(i \neq k\) （非真实标签位置）时： \[ \begin{aligned} \nabla \mathbf{h}_i = \frac{\partial \mathcal{L}}{\partial \mathbf{h}_i} &= -\frac{\alpha}{V} \sum_{j \neq k, j \neq i} \frac{1}{\mathbf{q}_j} \cdot \frac{\partial \mathbf{q}_j}{\partial \mathbf{h}_i} - \frac{\alpha}{V} \cdot \frac{1}{\mathbf{q}_i} \cdot \frac{\partial \mathbf{q}_i}{\partial \mathbf{h}_i} - \left(1 - \alpha + \frac{\alpha}{V}\right) \cdot \frac{1}{\mathbf{q}_k} \cdot \frac{\partial \mathbf{q}_k}{\partial \mathbf{h}_i} \\ &= -\frac{\alpha}{V} \sum_{j \neq k, j \neq i} \frac{1}{\mathbf{q}_j} (-\mathbf{q}_j \mathbf{q}_i) - \frac{\alpha}{V} \cdot \frac{1}{\mathbf{q}_i} \cdot \mathbf{q}_i (1 - \mathbf{q}_i) - \left(1 - \alpha + \frac{\alpha}{V}\right) \cdot \frac{1}{\mathbf{q}_k} (-\mathbf{q}_k \mathbf{q}_i) \\ &= \frac{\alpha}{V} \sum_{j \neq k, j \neq i} \mathbf{q}_i - \frac{\alpha}{V} (1 - \mathbf{q}_i) + \left(1 - \alpha + \frac{\alpha}{V}\right) \mathbf{q}_i \\ &= \mathbf{q}_i - \frac{\alpha}{V} \end{aligned} \]

整理上述两项，对任意分量 \(i\) 的梯度表达为： \[ \nabla \mathbf{h}_i = \begin{cases} \mathbf{q}_i - \frac{\alpha}{V} - 1 + \alpha, & \text{if token } i \text{ is the ground truth} \\ \mathbf{q}_i - \frac{\alpha}{V}, & \text{otherwise} \end{cases} \]

结合前面定义的真实分布 \(\mathbf{p}_i\)，上式可以精简并统一表示为向量级别的逐元素减法： \[ \mathbf{g} = \nabla_{\mathbf{h}} \mathcal{L} = \mathbf{q} - \mathbf{p} \]

1.2 Reduce synchronization

1.2.1 Rewrite Reduction: LayerNorm

forward


  • 朴素实现方式：
    • 先计算均值，再基于均值计算标准差。
    • 需要两次 kernel 内同步。
  • 改进实现方式：
    • 利用公式 \(\sigma(x) = \sqrt{\mu(x^2) - {\mu(x)}^2 }\) ，即：标准差/方差等于“平方的均值”减去“均值的平方”。
    • 线程在同一趟遍历中，可以同时并行累加 \(x_i\) 的和以及 \(x_i^2\) 的和，一次性同时求出均值 \(\mu(x)\) 和平方均值 \(\mu(x^2)\)。只需要一次 kernel 内同步。
    • 数值精度：存储采用 FP16，而内部累加计算采用 FP32 以保证精度。

backward


符号含义说明：

  • \(\mathbf{x}\) 与 \(x_i\)（输入特征）：
    • \(\mathbf{x}\)：LayerNorm 的输入特征向量（如一个 Token 的隐藏层向量）。
    • \(x_i\)：输入向量中第 \(i\) 个通道/维度上的具体数值（\(i = 1, 2, \dots, m\)）。
    • \(x_j\)：求和公式中用于遍历所有通道的下标符号。
  • \(\mathbf{y}\) 与 \(y_i\)（输出特征）：
    • \(\mathbf{y}\)：LayerNorm 归一化并缩放平移后的输出特征向量。
    • \(y_i\)：输出向量中第 \(i\) 个维度的具体数值。
  • \(m\)（特征维度大小）：
    • 隐藏层向量的总维度/通道数（Hidden Dimension Size，即向量 \(\mathbf{x}\) 里一共有多少个元素）。在求均值和方差时作为分母除数 \(\frac{1}{m}\)。
  • \(i, j\)（通道下标索引 Index）：
    • \(i\) 代表我们当前正在计算的那个特定通道。
    • \(j\) 代表在做全局求和（\(\sum_j\)）时遍历的所有通道（从 \(1\) 到 \(m\)）。
  • \(w_i\)（缩放权重 Weight / Gamma \(\gamma\)）：
    • 模型可学习的缩放系数，用来恢复模型的表达能力。\(w_i\) 是第 \(i\) 个通道专属的权重。
  • \(b_i\)（平移偏置 Bias / Beta \(\beta_{\text{bias}}\)）：
    • 模型可学习的偏移量。\(b_i\) 是第 \(i\) 个通道专属的偏置。
  • \(\mu(\mathbf{x})\)（均值 Mean）：
    • 输入向量 \(\mathbf{x}\) 在所有通道上的平均值：\(\mu(\mathbf{x}) = \frac{1}{m} \sum_{k=1}^m x_k\)。
  • \(\sigma(\mathbf{x})\)（标准差 Standard Deviation）：
    • 输入向量 \(\mathbf{x}\) 在所有通道上的标准差：\(\sigma(\mathbf{x}) = \sqrt{\frac{1}{m} \sum_{k=1}^m (x_k - \mu(\mathbf{x}))^2}\)。
  • \(\sigma(\mathbf{x})^2\)（方差 Variance）：
    • 标准差的平方，即输入的方差。
  • \(\hat{\mathbf{x}}_i\)（归一化后的临时特征）：
    • 零均值、单位方差的标准特征：\(\hat{\mathbf{x}}_i = \frac{x_i - \mu(\mathbf{x})}{\sigma(\mathbf{x})}\)。
  • \(\nabla y_i\) 或 \(\nabla \mathbf{y}_i\)（上层传回的梯度）：
    • 损失函数 \(\mathcal{L}\) 对 LayerNorm 输出 \(y_i\) 的偏导数 \(\frac{\partial \mathcal{L}}{\partial y_i}\)（由网络后续层反向传回）。
  • \(\nabla x_i\) 或 \(\nabla \mathbf{x}_i\)（需要求解的梯度）：
    • 损失函数 \(\mathcal{L}\) 对 LayerNorm 输入 \(x_i\) 的偏导数 \(\frac{\partial \mathcal{L}}{\partial x_i}\)（求出后继续向前传递给上一层）。
  • 原始形式：
    • 第二项 sum 依赖于 mean/std，需要两次同步。
  • 变换后形式：
    • 第二项 sum 依赖于输入，只需要一次同步。

1.2.2 Rewrite Reduction: Softmax Forward

传统 Safe Softmax 的计算痛点（3 趟遍历 + 2 次同步）

为了防止浮点数指数运算 \(e^{x_i}\) 发生 overflow，实际工程中必须使用数值安全的 Safe Softmax： \[ y_i = \text{Softmax}(x_i) = \frac{e^{x_i - m}}{\sum_{j=1}^N e^{x_j - m}} \quad \text{其中 } m = \max_{j} x_j \]

在未优化的传统实现中，这一过程需要 3 趟数据遍历（3 Passes） 和 2 次线程同步屏障：

  1. Pass 1 (Max Reduction)：遍历整行元素，找到最大值 \(m = \max(x_j)\)。此时需要 第 1 次线程同步，等待所有线程拿到全局最大值 \(m\)。
  2. Pass 2 (SumExp Reduction)：再次遍历整行，计算减去最大值后的指数和 \(S = \sum e^{x_j - m}\)。此时需要 第 2 次线程同步，等待所有线程拿到全局和 \(S\)。
  3. Pass 3 (Element-wise Division)：第三次遍历，计算最终归一化结果 \(y_i = \frac{e^{x_i - m}}{S}\)。

优化实现：

  • Parameters (e.g. # of blocks, warps per block) are shape dependent for maximal speedup.
  • 根据 dim 大小进行不同 kernel template 特化，以加速计算过程。


1.3 Mixed-precision Calculation

  • Modern GPU supports half-precision (FP16) or FP8 (on H100)
  • Benefits
    • lower memory for storing model and data ==> enlarge batch size.
    • transfer data at a higher rate (with same bandwith) between GPU main memory and SMs.
    • more FLOPs for FP16 (up to 8x more) compared to FP32.

低精度适用范围：

  • Forward / Backward could use FP16 or FP8.
  • Gradient update in Optimizer (or trainer) needs FP32.
  • Nvidia APEX library provides automatic mixed-precision calculation for many NN layers.
    • but still miss fine-grained memory optimization with mixed-precision for LLM.

Accelerated Mixed-Precision Update


  • 朴素实现：
    • 需要在显存中额外维护一份完整 FP32 浓度的 主权重（Master Weights）与主梯度。更新时需要将 FP16 参数与梯度复制成 FP32，用 FP32 更新完主权重后，再复制回 FP16。
    • 频繁的 Kernel Launch 与内存搬运：传统实现中，模型每个层/张量（Tensor）都是独立分散存放的，每次参数更新会为每个张量单独启动一次 CUDA Kernel，导致产生上百/上千次内核启动与昂贵的显存复制（Memory Copy）开销。
  • LightSeq2：
    • 存储层面：显存中仅保持 FP16 的参数和梯度。
    • 计算层面：在 GPU 寄存器内部以 FP32 精度进行高精度的累加与更新计算。
    • 连续内存空间 (Continuous Space) 将模型所有层的 FP16 参数和梯度平铺映射到一段 连续的内存空间（Workspace） 中，取代原先分散独立的张量内存布局。
    • 单个内核一次性更新 (Only One Kernel Launch) 由于所有的参数和梯度都在连续内存空间中，整个 Optimizer 参数更新过程不再逐张量 Launch，而是全局仅发起 1 次 CUDA Kernel Launch，完成全模型所有参数的更新。
    • 消除显存实体备份 (Dotted lines: no actual memory storage) 上图中的虚线框表示 没有实际的 FP32 主权重/主梯度显存实体。Kernel 在读取 FP16 数据后，在寄存器中直接转换为 FP32 完成更新，并直接写回 FP16 显存中，消除了 FP32 内存实体的占用。

1.4 Memory Reuse

GPU Memory Management for Self Attention Backward


  • backward 计算时
    • 识别出生命周期结束的张量。
    • 将后创的梯度张量直接写入原张量的显存地址中。
    • 大幅减少了训练阶段反向传播的显存峰值，使得 GPU 能够容纳更大的 Batch Size 或更长的输入序列 \(L\)。

2. Fast Inference for Transformer

2.1 Hierarchical Auto Regressive Search (HARS) for decoding

Beam Search 存在的问题

在传统的 Beam Search 解码中，每一步生成都需要：

  1. 计算当前 Beam 中所有候选词的条件概率分布（Softmax）。
  2. 计算累计序列概率，并在全局的 \(k \times V\) 个候选元素中选出得分最高的前 \(k\) 个序列（Top-\(k\)）。
  3. 存在的问题：当词表 \(V\) 很大（如 30,000+）时，直接对 \(k \times V\) 个元素进行全局排序（Direct Sorting）会在 GPU 上引发巨大的显存访存开销与线程同步等待。

HARS 的核心思想

HARS 的核心优化策略是 “先粗筛过滤，再局部精排” （retrieve and re-rank）：

  • 不再直接对全部 \(k \times V\) 个元素执行昂贵的全局 Top-\(k\) 排序。
  • 将大规约排序拆解为 并行 Max 过滤（Retrieve） 与 小规模候选重排（Re-rank），减少最终需要参与排序的元素数量。

算法流程：

第一步：检索阶段 (Retrieve Step)

  1. 分组 (Divide Groups)：将每个 Beam 的 \(V\) 个 Logit 划分为 \(G\) 个小组。
  2. 组内求最大值 (Group Maximums)：计算每个小组内的最大值，记为 \(m_i\)。
  3. 求阈值 (Rough Lower Bound)：求当前 Beam 中所有小组最大值 \(m_i\) 中的最小值，记作粗略截断阈值 \(m_{\min}\)。
  4. 粗筛过滤 (Filter)：只筛选出大于 \(m_{\min}\) 的 Logit，并写入 GPU 候选内存中，丢弃大部分极低概率的词。

第二步：重排阶段 (Re-rank Step)

  • 对粗筛后保留下来的少数字候选 Logit 执行最终的 Top-\(k\) 排序（Re-rank）。


2.2 Details in GPU Inference Implementation

  • share tensor memory across layers
  • mixed precision computation, mostly using FP16 for computation
  • Using float4 and half2 to increase bandwidth
  • No need to keep intermediate results and gradients during infernece, similar to with torch.no_grad()
