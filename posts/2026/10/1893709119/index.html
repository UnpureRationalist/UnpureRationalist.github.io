LLM Systems Assignment 5: Distributed Training and Fine-Tuning

本次 homework 的任务是：实现 DP/PP/LoRA 的核心代码，整体代码量非常少，本文对实现要点和一些注意事项进行介绍。

1. Data Parallel

DP 部分的待实现代码非常简单，唯一需要提一点的是 ranndom 的相关使用方法：作业规定了不能使用普通的 random.shuffle 而是必须手动从指定 seed 构造 gen = random.Random(seed) 对象，然后调用 gen.shuffle(lst) 进行随机顺序打乱，这是因为：

  • random.shuffle 依赖于全局的 random state（seed），其是每个进程启动是随机初始化的，每个进程不同。
  • DP 在进行数据集划分时，需要保证全量数据集被不遗漏不重复的均匀划分到每个进程，partition_indices 函数使用单独的 seed 和 random stage，就是为了让每个进程计算得到的数据集 index shuffle 结果完全相同，然后每个进程取自己 rank 对应的 index 进行数据读取即可。

2.2 Pipeline Forward and Backward

2.2.1 StageWorker 接口

runtime.py 的 StageWorkers 是流水线执行引擎。每个 stage 一个后台线程，每个线程拥有两个队列（任务、结果）。

  • submit(stage, fn)：无参 callable 塞进任务队列，立刻返回，非阻塞。
  • receive(stage)：阻塞等结果（30s 超时）；worker 里抛的异常原样 raise。
  • close()：往队列塞 None 哨兵让 worker 退出。

几个直接影响写法的细节：

  • CUDA 当前 device 是线程局部的，worker 自己 with torch.cuda.device(...) 绑卡。所以提交的函数里算 tensor 不用每次显式 .to()。
  • 梯度开关也是线程局部的。submit 时记录主线程此刻的 is_grad_enabled()，worker 执行前 set_grad_enabled 还原。
  • worker 用 try/except BaseException 把异常打包成 (False, exc)，receive 再 raise。所以 forward 里不用写 try/except。

2.2.2 Python lambda 特性

Python lambda 特性是：闭包晚绑定。lambda: model(micro_input.to(dev)) 里那几个名字，lambda 体在执行时（worker 线程，比定义晚）才读，那时循环早跑到最后一轮，所有 lambda 看到同一份最后的值。正确实现方式是在 submit 时把参数作为 xxx=xxx 显式初始化，这样参数立即求值构造为可调用对象提交到后台线程：

lambda 体只能是表达式，不能是语句。如果在 lambda 里填写： lambda ...: outputs[(m,s)] = model(x)，会报错：语法错误——赋值是 statement。正确实现方式是 lambda 只算并返回，结果在 receive 时保存。

跨设备 .to(dev) 一定写进被提交的 callable 里，让传输在 worker 线程、和各 stage 并行。

2.2.3 实现

一个 wave 循环，每拍先全 submit 再全 receive：


  • 数据依赖跨 wave。(m,s) 的输入是上一 stage 的 (m,s-1)，而 (m,s-1) 在上一拍（m+s-1）已经 receive 进 outputs。所以这次 submit 读 outputs[(m,s-1)] 时一定存在。outputs 字典在拍间传中间结果。
  • 先提交完整 wave 再接收，以让各个 worker 并发执行。
  • 一个 stage 一拍里最多出现一次，结果队列 FIFO，所以 receive 回来的就是当前 (m,s) 的结果，按与 submit 相同顺序 receive 即可获得结果。
  • 不要 detach。micro_input.to(dev) 保留计算图，跨 stage 梯度链才连得上，bwd 才能把梯度传回输入和各 stage 参数。
  • 拼接按 m 递增正好是原始顺序，最后在 self.devices[-1] 上 cat。

3. DeepSpeed ZeRO and LoRA

3.1 测试 DeepSpeed 初始化流程及与 TODO 代码交互关系

任务 3 的主要测试代码在：grading/distributed.py，其中涉及到 DeepSpeed 初始化以及调用我们需要实现的 TODO 代码。具体解释如下：

  • 测试启动流程：
    • main() 先用 socket.bind(("127.0.0.1", 0)) 检测一个空闲端口供 DeepSpeed 使用；进程组汇合用一个临时目录下的私有文件 store（init_method="file://..."）。
    • mp.spawn(worker, nprocs=2) 起两个进程，把 port、store、case、accelerator 传进去。
    • 每个 worker(rank, ...) 先写 MASTER_ADDR/PORT/RANK/LOCAL_RANK/WORLD_SIZE 环境变量，set_device(cuda:rank)，然后 dist.init_process_group("nccl", init_method="file://"+store, rank=rank, world_size=2, timeout=90s)。CPU 运行时后端是 gloo。
    • torch.manual_seed(123) 固定随机种子，建 net = model() 和它的 ref 副本、loss_fn = MSELoss()。
  • 与 TODO 代码交互关系：
    • zero_runtime / zero_updates 分支：先 reference_adapters(net) 用 grader 自己的 LoRALinear 包住 net[0]、net[2]（net.requires_grad_(False)，所以只有 lora_A/lora_B 可训），ref = deepcopy(net) 作为单进程参考。optimizer = SGD(可训练参数)。
    • 配置来源：zero_runtime 用 finetune.build_config(2, 2, 2, "fp32")，即调 TODO 的 build_config 函数。
    • engine = deepspeed.initialize(model=net, optimizer=optimizer, config=config, dist_init_required=False) 把模型和 SGD 包成 DeepSpeedEngine（内部是 DeepSpeedZeroOptimizer）。
    • 训练循环里，zero_updates 每个 microbatch 调 TODO 的 train_microbatch(engine, 切片, ...)。
