首先看 class Mul(Function) 的 forward 与 backward 方法：

  • forward：保存输入 Tensor a/b 供 backward 时使用，然后使用 TensorBackend 内注册的 op 进行计算，返回结果 Tensor（此时的 Tensor 仅完成了纯数学上的计算，还没有进行计算图相关操作）。
  • backward：提取保存的输入 Tensor a/b，调用相应 op 进行链式法则梯度计算。

然后看接口 class Function 的 apply 方法，其调用了实现类的 forward 方法并构建计算图。

  • 遍历输入 Tensor，如果其中一个需要梯度，那么结果 Tensor 也需要计算梯度。同时调用 detach() 方法，获取输入 Tensor 的一个 constant 视图。
  • 构造 Context 对象，传入是否需要梯度参数。
  • 调用实现类 forward 方法，完成前向计算。
  • 如果需要计算梯度，构造 History 对象（否则为 None），保存 Function class、context 以及输入 Tensor 列表，供 backward 时使用。class History 包括三个成员：
    • last_fn：计算结果 Tensor 由哪个 Function 计算出来，用于链式法则计算梯度。
    • ctx：保存计算梯度需要用到的 Tensor，通常需要保存输入 Tensor 以及部分中间计算结果，供 backward 时使用以让 backward 实现更加简洁。ctx 内保存到 Tensor 是 detach 之后的纯数值引用，无计算图相关成员。
    • inputs：保存计算得到该 Tensor 的所有输入 Tensor。这里保存的 Tensor 是带有 history 成员的携带计算图历史的原始输入 Tensor，不同于 ctx 中 detach 后的 Tensor。class Tensor 的 parents() 方法即返回 self.history.inputs，autodiff.py 内待实现的的 topological_sort 函数最终调用的就是 Tensor 的相关方法。
    • ctx 与 inputs 保存的 Tensor 分别服务于两个目的：
      • 纯数值计算
      • 计算图构建
    • 下文称这个特性为 ctx 双通道
  • 根据数值计算结果 Tensor 和 History 对象，返回最终的结果 Tensor，进行可能的计算图构建。

3.2 其他 Function 实现总结

tensor_functions.py 中共有 18 个 Function 子类。它们共享 3.1 节剖析过的同一套骨架（apply 建图 + ctx 双通道），差异只在两处：forward 算什么、backward 存什么/算什么导数。本节按"backward 需要什么信息、如何表达导数"对全部 Function 做分类总结。

分类总览

类别 Function 导数表达形式
A. 可导为输出表达式的标量映射 Neg, Add, Mul, Inv, PowerScalar, Exp, Tanh, Sigmoid 用 forward 的输出（或输入的简单组合）直接表达 f'(x)
B. 依赖输入符号的分支函数 ReLU, Log 导数是分段函数，需保留输入并走 _back 内核
C. 归约与折叠 Sum, All, Max(nn.py) 广播回填 / 掩码回填
D. 不可导的谓词运算 LT, EQ, IsClose 梯度恒为零（阶梯函数）
E. 结构变换（不碰数值） View, Permute, Copy 重排梯度形状 / 恒等
F. 多维收缩 MatMul 矩阵求导：dL/dA = G·Bᵀ, dL/dB = Aᵀ·G

A 类：导数可用输出表达式表达的标量映射

这一类的共同特征：f'(x) 能写成 x 或 f(x) 的解析式，ctx 只需存一份值。

Neg / Add —— 零记忆优化（不存任何东西）：

导数是常量（-1 / +1）的运算完全不需要 ctx——上游梯度经过一个仿射变换即可。Add.backward 返回两个梯度对应两个输入，inputs 顺序与 backward 返回顺序一一对应（assert len(x) == len(h.inputs)）。

Mul / PowerScalar：存输入，导数是输入的组合：

注意 PowerScalar.backward 返回 (grad_a, 0.0) 中的 0.0：常量输入的"梯度"是占位符，个数必须对齐，值由 Tensor.expand 分发时被 is_constant 判断丢弃。

Exp / Sigmoid / Tanh：存输出，导数是输出的函数（数值稳定性的体现）：

σ'(x) = σ(x)·(1-σ(x)) 这个恒等式是"存输出"策略的数学基础——输出能反推导数时，存输出和存输入等价，但存输出可以复用 forward 已经算好的值。Tanh 同理（tanh'(x) = 1 - tanh²(x)，代码里 -(out**2) + 1）。Exp 存输出则因为 e^x 的导数就是它自己，直接省一次 exp 计算。这是每个 Function 作者的优化决策点：导数有几种等价表达，选计算/存储最省的那种。

B 类：导数是分段函数——存输入，走 _back 内核

ReLU 的导数 x>0 ? 1 : 0、Log 的导数 1/(x+EPS) 都无法用输出表达（ReLU 的输出 0 对应两种输入状态：负数和恰好为 0），所以必须存输入并依赖 operators.py 里的分支标量函数 relu_back(x, d) = d if x > 0 else 0.0。这一类与 operators.py 的 _back 系列函数一一对应——分段导数的分支逻辑被隔离在标量内核里，张量层只见统一的 zip 调用。

Function 存什么 为什么
Neg / Add 什么都不存 导数是常量
Mul / PowerScalar 输入 导数是输入的组合
Exp / Sigmoid / Tanh 输出 导数可用输出表达（恒等式）
ReLU / Log / Inv 输入 导数是分段函数 / 无法由输出反推

C 类：归约的梯度——"广播"或"掩码"回填

Sum 的 backward 看似"原样返回"，实际依赖 Tensor.expand 的广播回填：forward 把 shape (b, n) 沿 dim 压成 (b, 1)，backward 拿到的梯度也是 (b, 1)，分发回输入 (b, n) 时沿被压维度广播复制——"求和的梯度 = 每个被加项各得一份"，这正是求和的导数定义。归约的导数 = 广播，是 minitorch 里最优雅的对偶。

nn.py 里的 Max 则是另一种回填——掩码式：

max 的导数不是处处可导的，取其次梯度：梯度只流向最大值位置（(out == input) 产生 one-hot mask，0/1 mask 乘上游梯度即实现）。对照 Sum（人人有份）和 Max（胜者通吃），是"归约如何反传梯度"的两种极端答案。

D 类：谓词运算——梯度恒为零

lt/eq/is_close 是比较运算，数学上是阶梯函数，几乎处处导数为 0——backward 返回正确形状的全零梯度即可。存 shape 而不存数据是这类函数的共同优化：backward 只需要知道"梯度该长成什么形状"，不需要任何数值。它们存在的意义是让 dropout mask、argmax one-hot 等运算可以进入计算图（前向有值、反向透明），并让 ==、< 等运算符重载可用。

E 类：结构变换——数值不动，只动 shape/strides

这一类 Function 的 forward/backward 都是零数据拷贝的：View 用原形状重新解释 storage，Permute 的 backward 就是"用自己的逆变换"。它们体现了 shape/strides 表示法的核心红利——形状变换可以只是元数据的重排。Copy（contiguous()）是本类中唯一可能真正拷贝数据的（当输入非连续时），其 backward 是恒等映射。

F 类：MatMul——真正的矩阵求导

线性代数结论 L = AB, dL/dA = G·Bᵀ, dL/dB = Aᵀ·G（G 是上游梯度）的直接实现。注意 transpose 是用 permute 实现的零拷贝转置（只交换 shape/strides 两个元素）——E 类的结构变换在这里成为 F 类导数计算的原语，两层设计互相成就。

横向对比：一张表看 ctx 存什么

把全部 Function 按"backward 需要什么"排成一张决策表，这张表其实就是写一个新 Function 时的思考清单：

Function ctx 保存的内容 backward 的导数来源
Neg / Add / Copy 无（或恒等） 导数是常量/恒等
Mul / PowerScalar 输入 输入的组合（乘法法则）
Exp / Sigmoid / Tanh 输出 输出的恒等式（σ(1-σ)、1-tanh²、e^x）
ReLU / Log / Inv 输入 分段/非线性函数，走 _back 内核
Sum 输入的 shape + dim 广播回填（不需要数据）
Max 输入 + 输出 one-hot 掩码（需要比较两者）
LT / EQ 输入的 shape 全零（阶梯函数）
View / Permute 原始 shape / 逆序 形状重排（不需要数据）
MatMul 两个输入 G·Bᵀ / Aᵀ·G（需要数据做矩阵乘）

规律：ctx 存什么完全由"f'(x) 的最省表达形式需要什么"决定——能省则省（Neg 不存）、能存输出不存输入（输出是 forward 副产品）、能存 shape 不存数据（结构变换）。所有 Function 的 backward 都在"读 ctx → 算局部导数 → 返回与 inputs 等长的梯度元组"这个模板里工作，差异只在数学本身。

  • class Variable(Protocol) 定义了 autodiff.py 模块需要用到的几个方法。可以结合 class Tensor 的实现理解，这里简单说明下：
    • is_constant()：表示节点是否是常量。
    • is_leaf()：表示节点是否是 Parameter。Tensor 内部实现判断逻辑为：self.history is not None and self.history.last_fn is None。构造 Parameter 对象时，内部会调用 Tensor 的 requires_grad_ 方法：self.history = History() if require_grad else None，让一个 Tensor 变成叶子节点。注意，这里的叶子节点概念不同于数据结构中树/图的叶子节点（DAG 表示中的叶子节点），而是既要是 DAG 中的叶子节点，又要是可学习参数才可以（训练输入数据和标签 x/y 在 DAG 角度也是叶子节点，但是 Tensor 角度而言其是 is_constant() 而不是 is_leaf()）。
    • accumulate_derivative：用于叶子节点梯度累加。
    • parents：获取当前 Tensor 的输入 Tensor。
    • chain_rule：
  • topological_sort 接受 forward 形成的 DAG 的最后一个 Tensor 作为参数，以深度优先搜索方式遍历 DAG（同时需要过滤掉 is_constant() 的不需要求梯度的节点），形成一个拓扑序的 Tensor 列表。需要注意的是，最后返回 Tensor 列表时需要 reverse 下，因为 backpropagate 内部进行反向传播梯度计算时，要从 DAG 的最后一个节点（即绝大多少情况下的 loss 节点）反向进行。
  • backpropagate 接受 DAG 最后一个节点（loss 节点）和上游传递下来的梯度（从只有一个元素的 loss Tensor 调用 backward() 时，传入 Tensor.make([1.0], (1,), backend=self.backend) ，即梯度 1.0）。其内部实现流程大概如下：
    • 调用 topological_sort 函数获取从后向前的 Tensor 列表
    • 定义一个 dict，保存输入 Tensor id 到输入 grad 的映射关系
    • 遍历列表中的每一个节点
      • 如果该节点为叶子节点，进行梯度累加
      • 否则（即对于计算图的中间节点），调用节点的 chain_rule 方法进行链式梯度向父节点传播，保存 chain_rule 返回的非 is_constant() 节点的 Tensor id -> grad 映射到 dict 供后续使用。
  • 值得一提的是，backpropagate 的实现对叶子节点（Parameter）与 DAG 的中间节点采用了两套截然不同的处理逻辑：
    • 对叶子节点，进行梯度累加。
    • 对中间节点，使用适当数据结构临时保存其 grad。
    • backpropagate 调用完成后，中间节点的梯度值不复存在（被 gc 回收掉）；而叶子节点的梯度被累加到 class Tensor 的 self.grad 成员上。
    • 有两个主要原因导致了这种实现方式：
      • 从 目的 来看，DAG 计算图是实现 autodiff 的一种方式，计算图构建和中间节点的梯度，只是计算图这种实现方式必不可少的中间步骤，而最终的目的只是对可学习参数 Parameter 求梯度，因此只有 is_leaf() 的 Parameter 节点需要进行梯度累加，而中间节点的梯度只是为了得到 Parameter 梯度必须得到的中间计算结果。因此，backpropagate 方法内临时保存中间节点的梯度，以能够计算得到 Parameter 的梯度。反向传播完成后，loss Tensor 连带着其引用的计算图全部析构，只有预先定义的神经网络（带有很多 Parameter）的梯度保留，供优化器进行梯度下降。
      • 这种实现方式，还天然允许了 梯度累积：多次 minibatch，每次 minibatch forward 完成后对 loss 调用 backward 累加梯度到 Parameter；多个 minibatch 结束后调用一次优化器的 step() 与 zero_grad() 方法，在内存有限的情况下实现大 batch 训练效果。

4.2 Module

要点总结：

1. 核心机制：赋值即注册，类型分流

__setattr__ 按值的类型（而非属性名）把赋值分到三个去处——Parameter 进 _parameters、Module 子类实例进 _modules、其他类型走 super().__setattr__() 成为普通属性。因此子类（如 Linear/Network）不需要任何手工登记代码，self.weights = RParam(...) 一行就完成注册。配套的 __getattr__ 在正常属性查找 miss 后按 _parameters → _modules 顺序补偿查找，保证读写对称。

2. 两个细节

  • 注册写入必须直接操作 self.__dict__["_parameters"]，不能写 self._parameters[k] = val——后者本身是一次属性赋值，会再触发 __setattr__ 造成无限递归。
  • __getattr__ 只在正常查找失败后才被调用（Python 属性协议：实例 __dict__ → 类属性 → __getattr__ 兜底）。被 __setattr__ 拦进注册表的属性不在实例字典里，正好走这条补偿路径。

3. Parameter 构造即建图叶子

Parameter.__init__ 副作用调用 value.requires_grad_(True)——即挂一个空 History()（last_fn=None），使该 Tensor is_leaf()==True（梯度终点）、is_constant()==False（参与求导）。"参数自动进入计算图"的机制落点就在这一行，用户完全无感。Parameter.update() 对新值重复同样的操作，因为优化器的 p.update(p.value - lr*grad) 是整值替换（新 Tensor 是干净节点，需重新标记为叶子），而非原地修改。

4. named_parameters()：DFS 收集 + 路径命名

先收本层 _parameters，再深度优先递归子模块、用 f"{mod_name}.{k}" 拼接路径前缀，产出形如 ("linear1.weights", W1) 的 (完整路径, Parameter) 列表——与 PyTorch state_dict 的键风格一致。parameters() 丢弃名字只留值，是优化器的直接接口（Adam(self.model.parameters(), lr)）。注意 modules() 只返回直接子模块（不递归），递归遍历由 train()/eval() 手工完成。

5. train()/eval()：模式标志沿树广播

递归设置整棵树的 training 标志。在 HW2 中的唯一消费点是 dropout 的 ignore 参数：nn.dropout(h2, prob, not self.training)——eval 模式跳过随机丢弃。这也是"模型模式"与"算子行为"解耦的体现：Module 层只维护状态，具体哪个算子消费这个状态由算子自己决定。

6. 与 PyTorch 的对应关系（教学实现的简化处）

本实现 PyTorch 差异
__setattr__ 类型分流注册 同款机制 相同
__getattr__ miss 时返回 None miss 时 raise AttributeError minitorch 拼错属性名不会报错，静默得 None
Parameter.update() 整值替换 原地 data.copy_()/add_() minitorch 每次替换产生新 Tensor 节点，旧图作废
modules() 非递归 递归全树 minitorch 简化，全树遍历靠 train/eval 手工递归
__repr__ 树形打印 同款格式 minitorch 只打印子模块骨架，不列参数
